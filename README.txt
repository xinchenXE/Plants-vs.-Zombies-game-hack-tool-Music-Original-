Funky Stars  —  原版 (Hybrid song 2:20)
================================================================

一个 25 KB 的独立播放器，内嵌整首曲子，双击即放，不释放任何临时文件，
不需要任何运行库、声卡驱动之外的依赖。

文件
----------------------------------------------------------------
  FunkyStars_Original_upx.exe   25,600 字节   <- 交付物（双击这个）
  FunkyStars_Original.exe       57,856 字节      未加壳，内容完全相同
  FunkyStars_Original_preview.mp3  试听用，非交付物

  歌曲时长约 140 秒，播完自动退出。


技术参数
----------------------------------------------------------------
  可执行格式   PE32 (i386 / 0x14C)
  链接方式     -nostdlib，自写入口 __start，无 C 运行时
  导入表       仅 winmm.dll + kernel32.dll + msvcrt.dll
  编译         llvm-mingw clang 23.1.3（i686, msvcrt）
               -Oz -flto -ffreestanding -fno-builtin -fno-ident
               -fomit-frame-pointer -Wl,-s
  加壳         UPX 5.2.1  --best --lzma    57,856 -> 25,600 (44.3%)
  音频输出     waveOut，44100 Hz / 16 bit / 立体声
  缓冲策略     16 块 × 0.25 秒 = 4 秒预读，边播边补，始终维持满队列

音质验证
----------------------------------------------------------------
以 libopenmpt 0.7.21 (openmpt123) 的 44.1 kHz 渲染作为参考，并把它拆成
10 个"单声道 solo"逐条比对（10 个 solo 相加与完整混音的 RMS 比值为 1.0001，
所以这套拆分是可信的）。

  整曲 RMS            参考 7081.1   本程序 7043.8   (比值 0.9947)
  100 ms 窗口比值中位                    1.002
  落在 ±2 dB 内 (0.8~1.25) 的窗口          98.5%  (1402 个窗口)
  |比值-1| 中位                            0.043
  9 个倍频程频段偏差   +0.10 / +0.35 / +0.42 / +0.22 / +0.34
                       +0.08 / -0.40 / -1.01 / +2.33  dB
  左声道 100 ms 匹配                       99.3%
  右声道 100 ms 匹配                       98.4%
  立体声宽度 (side/mid)  参考 0.177~0.186   本程序 0.180~0.183
  时间漂移            140 秒内累计 12 ms（tick 长度 848.077 截断成 848 所致）

  逐声道包络相关系数：ch0 .993  ch1 .992  ch2 .995  ch3 1.000  ch4 .997
                      ch5 .999  ch6 .998  ch7 .997  ch8 .998  ch9 .998
  逐声道声像与参考的差都在 0.02 以内（ch0 .421/.422  ch3 .718/.723
  ch5 .502/.502  ch9 .597/.600 …），说明声像映射已经对齐。

  各频段偏差都在 ±1 dB 以内，唯一偏大的 10~20 kHz 是线性插值带来的
  镜像/混叠噪声；该频段在参考里本身只有 -48 dB（相对 40~80 Hz 低频），
  完全听不出来。

  为对齐参考电平并回收动态余量，输出级做了两件事：
    1) 一阶高通 fc≈12 Hz，滤掉采样自带的直流偏置（约 -700）；
    2) 整体增益标定为参考 RMS 的 1.00 倍。
  峰值处约 1000 个样本触及满刻度（参考本身削波 1293 个），属于原曲混音
  本身的电平，未做额外限幅。


调试过程中修掉的几个真 bug（都会明显影响听感）
----------------------------------------------------------------
  1) 声像律用错：写成了线性 pan/255，实测参考是常数功率（开方）律。
     线性律下左右分离过度，立体声宽度几乎是参考的两倍（0.35 vs 0.18）。
     改用 T[p]=sqrt(p/255) 的 256 项查表，宽度立刻对上。

  2) 音量精度截断：`v = vol*env/64` 一上来就把小数截掉，音量列只有 8、
     包络只剩 6 时 (8*6)/64 = 0，整条通道直接静音。输出级现在还保留
     32 倍精度（mix 里 >>13），否则余音收尾阶段同样会被截成 0。

  3) fadeout 步进少了一半：FT2 每 tick 的步进是乐器值的 2 倍。按 1 倍算
     所有音的释放长出一倍，整首的余音变得拖沓。

  4) 包络循环写成了"钳位"：`if (epos > 循环起点) epos = 循环起点` 会把
     包络冻在循环起点，循环段后面的点永远走不到。改成越界回绕。

  5) 采样音量被重复相乘：采样自带音量只是"音符触发时的默认通道音量"，
     音量列会覆盖而不是叠乘。原来再乘一次 smpVol/64，乐器 0 (47) 和
     乐器 6 (46) 的音符被压低 25%。

  6) 音符触发无条件重置音量：只有"指定了乐器"的音符才重置。像
     `B-5 00`（有音符、无乐器、无音量列）必须保持原音量，否则那一段
     会整体响 2.8 倍。

  7) OFF 晚一个 tick 才走释放段：参考在 OFF 所在的那一 tick 仍保持松键前
     的音量。早一个 tick 会让所有音的收尾短掉 19 ms。


构建（可选）
----------------------------------------------------------------
  i686-w64-mingw32-clang -Oz -flto -nostdlib -ffreestanding -fno-builtin \
    -fno-ident -fomit-frame-pointer -Wl,--entry=__start -Wl,-s \
    -Wl,--no-insert-timestamp -o FunkyStars_Original.exe src/main.c \
    -lwinmm -lkernel32 -lmsvcrt

  src/mod_data.h   <- tools/gen.py 从 hybrid_song.xm 生成
  src/tables.h     <- 同上，Amiga 周期表、乐器步进常数、常数功率声像表


附：调试开关
----------------------------------------------------------------
  -DTRACE       打印行事件
  -DSTATE       打印每 tick 通道状态
  -DSTEMS       把 10 个声道分离成裸 PCM（排查"缺乐器"用，见 tools/perch.py）
  -DRENDERTEST  把整曲渲染成裸 PCM 到 stdout（用来跑上面那套比对）
  -DPROBE=n     打印第 n 个声道每行的 vol/env/inst/fade

  tools/mksolo.py   把一个正常的 XM 拆成 10 个"只留一个声道"的 XM，
                    用 openmpt123 渲染后即可逐声道对齐比对。
